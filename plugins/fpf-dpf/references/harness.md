# Adaptive FPF/DPF collaboration

The main chat is the orchestrator and owns C.19.2, source selection, synthesis, and the answer. Sol medium is a useful orchestrator default when the user has not chosen a model; this reference never changes the active model. Start with the deterministic `corpus.py --snapshot ID status/catalog/search/read/route` workflow. The orchestrator refreshes once per task, pins the snapshot and reads its `USING-FPF.md` fully. Each delegated brief must identify that guide in the same snapshot; an agent selecting or applying methods reads it, without refreshing. Reuse a current reading only while unchanged and present in context. The corpus is dynamic across the whole pinned snapshot: new, renamed, and removed DPFs must be discovered from that snapshot. Do not assume a fixed DPF list.

Do simple analysis in the main chat. Delegate only when an independent retrieval, analysis, difficult interpretation, or focused review is likely to change a decision or support a required guarantee under C.19.2. Choose the least costly capable role: `scout` for bounded source discovery, `analyst` for substantive synthesis, `expert` for unusually difficult or high-consequence interpretation, and `reviewer` for a specific unresolved assurance claim. Escalate only for a stated reason. Use at most two simultaneous subagents; no recursive delegation. Delegation is available only if this runtime actually exposes `collaboration.spawn_agent` with `model`, `reasoning_effort`, and `fork_turns`. If a preset model is unavailable, disclose that and continue locally or ask for a choice when the capability difference matters; do not silently substitute a more expensive model. Never create user-visible threads or change global configuration for this workflow.

Get a preset with `scripts/run.ps1 role NAME` on Windows or `python3 scripts/harness.py role NAME` elsewhere. `--deep` selects medium for scout, high for analyst/reviewer, and xhigh for expert; use it only for a stated reason. Spawn with its model and effort, `fork_turns='none'`, and a short task brief containing the question, requested output, constraints, absolute plugin/data paths, pinned snapshot ID, and relevant source packet or selectors. Aim for a 250вЂ“500 word handoff when enough; this is a soft guide, not a token cap. Do not send full chat history. A subagent returns findings, exact source selectors and lines, uncertainties, and what further reading would resolve them. The orchestrator checks material claims against exact source text before using them. Check required prior results and relevant Reference examples or Practical-Use Cards when methods must connect; stop when the needed result is supported. Raise source coverage when evidence is missing; raising model effort cannot supply missing evidence.

`corpus.py --snapshot ID packet QUERY [--selector SELECTOR]... [--scope TEXT] [--limit 3] [--max-chars 18000] [--kind FPF|DPF] [--document ID]` supplies bounded JSON with exact source lines, selectors, snapshot/commit, hashes, partial flags, and `next_line`. A packet supports traceability, not semantic completeness. Inspect partial flags and paginate with snapshot-pinned `read` when the needed applicability, conditions, or counterevidence lies beyond the packet. Redirect large output to a file when useful. Keep source guarantees tied to exact lines; a compressed handoff is not source evidence.

For a resumable substantial task, an optional compact JSON run-state in the user's project may record the goal, required guarantees, decisions, source snapshot, open questions, and results. Do not create it for a small task or present it as a required artifact. Do not introduce Dots in this version.
